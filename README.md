# 🏭 RS-485 Sensors Polling API

Микросервис на **FastAPI** для фонового опроса промышленного оборудования по шине RS-485.

Проект спроектирован с упором на отказоустойчивость, чистую архитектуру (SOLID) и работу в условиях нестабильной физической связи.

## 🛠 Технологии
- **Python 3.11+**
- **FastAPI** (REST API)
- **PySerial** (работа с COM-портами)
- **Requests** (отправка данных на внешний сервер)
- **Docker** (Dev / Prod окружения)

## 📡 Поддерживаемое оборудование
Сервис умеет одновременно опрашивать приборы с разными протоколами на одной шине RS-485:
1. **ОВЕН СИ8** (протокол ОВЕН) — накопительные счетчики импульсов (расчет скорости конвейера).
2. **ОВЕН ПВТ-110-Н5-RS** (протокол Modbus RTU) — термогигрометры (мгновенные значения °C и %).

## 🏗 Архитектура

Устройство проекта выглядит следующим образом:
* **`app/owen_drivers/base_driver.py`** — абстрактный класс `BaseDriver`. Чтобы добавить новый прибор, достаточно отнаследоваться от него и реализовать протокол обмена.
* **`app/providers/`** — поставщики данных:
  * `BaseDataProvider` — Абстрактный класс провайдера.
  * `SerialDataProvider` — общается с реальным железом.
  * `MockDataProvider` — генерирует реалистичные тестовые данные (позволяет вести разработку без подключения к COM-порту).
* **`app/owen_poller/poller.py`** — крутит асинхронный `while` цикл и бережно опрашивает приборы, соблюдая паузы.
* **`app/owen_poller/device_registry.py`** — хранилище актуальных состояний датчиков (используется API-ручками).
* **`app/owen_poller/connection.py`** — отвечает за авто-переподключение COM-порта при обрыве кабеля.
* **`app/owen_poller/state.py`** — `SensorRuntimeState` хранит метрики успешности опроса (Success Rate), а `SensorMinuteSnapshot` - "снимок" состояния сенсора на конец минуты.
* **`app/owen_poller/sensor.py`** — связывает драйвер, порт связи и хранилище значений.

## 🚀 Запуск проекта (Docker)

Проект содержит два Dockerfile: для разработки (с линтерами и hot-reload) и для продакшена.

### 1. Локальная разработка (Mock-режим)
Чтобы тестировать API без физического RS-485 адаптера, убедитесь, что в `settings.py` установлен флаг `USE_MOCK_PROVIDER = True`.

```bash
# Сборка образа для разработки
docker build -t sensor-app:dev -f Dockerfile.dev .

# Запуск с пробросом кода для горячей перезагрузки (Hot Reload)
docker run -p 8000:8000 -v $(pwd):/code sensor-app:dev
```

### 2. Запуск на Production (с реальным железом)
Убедитесь, что в конфиге указан правильный COM-порт (например, `/dev/ttyUSB0` для Linux или `COM3` для Windows) и `USE_MOCK_PROVIDER = False`.

```bash
# Сборка легковесного боевого образа
docker build -t sensor-app:prod -f Dockerfile .

# Запуск с пробросом устройства внутрь контейнера (пример для Linux)
docker run -d --name phyhub-gateway -p 8000:8000 --device=/dev/ttyUSB0 sensor-app:prod
```

## 🧩 Как добавить новый прибор?

1. Создайте файл драйвера в `app/owen_drivers/`.
2. Создайте класс-наследник от `BaseDriver`.
3. Задайте `poll_priority` (очередность опроса) и `poll_interval` (как часто опрашивать).
4. Реализуйте методы `read_parameter` (запрос байт через `provider`), `calculate_instant_metric` и `get_status`.
5. Добавьте датчик в конфигурацию `settings.py` (раздел `sensors_settings`). 

Готово! Система автоматически подхватит его в цикл опроса и API.
